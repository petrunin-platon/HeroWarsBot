- два свайпа «вверх» ни разу не понадобились (`team_manager.py:93-96`);

- есть пауза 1,2 с.

Ваша идея — проверять только после паузы или ручного боя.

**Что сделать.**
1. Убрать свайпы «вверх».
2. Проверять слоты по **одному** снимку экрана.
3. Внутри сессии сборку пропускать, как и сейчас.
4. После мягкой паузы, ручного боя и при запуске — быстрая проверка или доверие игре (вопрос 10).
5. Полную перестановку делать только при несовпадении.
6. Вместо паузы 1,2 с ждать, пока иконка встанет в слот.

**Готово, когда:**
- тест проходит: поиск всех титанов на одном снимке экрана выбора команды;
- в игре:
  - первая комната каждой стихии дольше обычной не больше чем на 3 с (сейчас +11–26 с);
  - свайпов не видно;
  - если во время мягкой паузы руками убрать титана из слота, бот после паузы вернёт его.

**От вас:** скриншот экрана выбора команды (сетка титанов сверху и слоты снизу).

### Задача 8. Защита от зависаний и непонятных экранов
**Зачем.** Если на экране что-то неожиданное, бот может ждать бесконечно и никому не сказать.

**Что сделать.**

2. «Сторож»: если за 5 минут не пройдено ни одной комнаты — скриншот в `bot_data/debug/`,
   сообщение в окне программы и в Telegram, попытка «умного старта» (`main.py:recover_context`).
3. Если бот упал с ошибкой Python — напечатать ошибку и итог сессии.
4. После «Пройти руками» — по ответу на вопрос 12. Например, бот ждёт, пока вы вернётесь в коридор, и продолжает сам.

**Готово, когда:**

- в игре: откройте в игре любое окно (например, чат), пока бот в коридоре.

### Задача 9. Умнее тактика (после ответов на вопросы 1–3, 7–9, 11, 15, 16)

**Что сделать** (можно разбить на 2–3 сессии):

- **Опасные составы врагов:** против них сразу ставить пак посильнее (по истории боёв), а не ждать плохого боя.
- **Отхил:** выбирать, где и кем лечить, по правилам игры (вопрос 2). После отхила возвращать обычный пак.

`profile.yml`, `temp_sos.png` и `pause.flag` уже в `.gitignore` — с ними всё в порядке.

### Как сделать, чтобы они не мешали (задача 2)
1. **Одна папка для всего, что пишет бот,** — `bot_data/`, в `.gitignore`. В репозитории остаются только образцы:
   `profile.example.yml` и правила по умолчанию в `rules/`.
2. **Первый запуск после обновления.** Бот сам копирует ваши текущие `stats.json`, `rules/*.yml`, `logs/battle_log*`
   в `bot_data/`, если их там ещё нет. Ваши данные не теряются.
3. **Дальше** бот и окно программы читают и пишут только `bot_data/`. Обновления с GitHub больше не трогают ваши данные.
4. **Отдельный шаг, только после вашей проверки:** убрать старые копии из репозитория
   (`stats.json`, `profile.yml.bak`, `temp_test.png`, `logs/battle_log*`) и добавить их в `.gitignore`.
   Внимание: когда вы заберёте такое обновление, git удалит эти файлы у вас в папке. Поэтому шаг делаем, когда данные
   уже лежат в `bot_data/`. Для надёжности перед этим скопируйте `stats.json` и папку `rules/` в отдельное место.
5. **Ваши `.jsonl` и `.csv` от 18.10** лучше заранее перенести в `logs/session_01-02/`.
   Тогда они останутся в репозитории как часть вашего архива сессий.
6. **Чтобы прислать мне данные новой сессии,** копируйте нужное из `bot_data/logs/` в `logs/session_XX/`, как сейчас.

### Пока задача 2 не сделана

  1. скопируйте эти файлы в отдельную папку;
  2. в GitHub Desktop нажмите на файл правой кнопкой → «Discard changes»;
  3. заберите обновления (Pull);
  4. верните скопированные файлы на место.

### Про `assets/` в `.gitignore`
- Строка `assets/` в `.gitignore` теперь есть (раньше она была закомментирована).
- Картинки, которые уже в репозитории, git продолжит отслеживать.
