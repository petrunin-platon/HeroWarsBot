# CLAUDE.md — памятка для работы над HeroWarsBot

## Кто пользователь и как с ним говорить
- Пользователь не программист, пишет код с помощью ИИ.
- Объясняй простым языком, как старшекласснику. Пиши по-русски.
- Термины расшифровывай, а вместо длинных рассуждений давай короткие шаги.

## О проекте: главные факты
- Бот для Hero Wars на Python. Он проходит подземелье титанами.
- Игра идёт на Android-телефоне, подключённом к ПК (Windows) по USB.
- Экран телефона показывается в окне scrcpy с заголовком `HeroWarsBot_Arena`.
- Бот делает снимки этого окна (`mss`), ищет на них картинки-шаблоны через OpenCV (`cv2.matchTemplate`)
  и нажимает на телефоне через ADB (`adb shell input tap` / `swipe`).
- **Запустить бота здесь, в облаке, нельзя:** нет телефона, игры и scrcpy. Не пытайся. Проверяет пользователь сам у себя на ПК.
- **Картинки.** Полный набор — папка `assets/`, она есть в репозитории.
  - Файла с картинками в base64 (`assets_db.py`) сейчас в репозитории нет: его удалили 13.09.2026, он остался только в истории git.
  - На ПК пользователя его тоже нет: в логе строка «Файл assets_db.py не найден. Использую чтение с диска».
  - Если этот файл появится, бот будет брать картинки из него, а не из `assets/` (`vision.py:15-22`, `vision.py:146-163`).
    Тогда после замены картинки в `assets/` его нужно пересобрать или удалить.
- **`assets/` есть в `.gitignore`.** Картинки, которые уже в репозитории, git продолжает отслеживать.
  Новую картинку git не увидит — добавлять так: `git add -f assets/имя.png`.
- Если нужно знать, какие картинки есть, или нужны конкретные иконки — попроси пользователя, он пришлёт.
  Пиши точное имя файла и что на картинке должно быть.
- **`ui/`** — графическая оболочка. Пока её не трогаем. Исключение — если задача или пользователь прямо разрешили.
- **`logs/`** заполняет сам пользователь. Бот и окно программы в неё больше ничего не пишут и ничего в ней не удаляют.
- **`bot_data/`** (в `.gitignore`) — всё, что бот и окно программы пишут сами. Пути прописаны в `data_paths.py`:
  - `bot_data/stats.json` — статистика;
  - `bot_data/rules/*.yml` — рабочие правила (`rules/` в репозитории — правила по умолчанию, бот туда не пишет);
  - `bot_data/logs/` — история боёв (`battle_log_*.jsonl`, `battle_log.csv`), лог бота (`bot_log_*.txt`), замеры (`timings_*.csv`);
  - `bot_data/profile.yml.bak` — копия профиля (там токен Telegram);
  - `bot_data/titan_state.json` — ХП и энергия титанов после последнего боя, в пределах игрового дня (`titan_state.py`);
  - `bot_data/temp_sos.png`, `bot_data/temp_test.png` — скриншоты для Telegram.
  - `bot_data/debug/` — скриншоты для разбора: `sos_комната<N>_<стихия>_<время>.png` при каждом SOS, `result_unreadable_...png`, если окно результата не прочиталось, и `stuck_...png` при зависании (сторож, задача 8). Бот их не удаляет.
  - Новые файлы бота тоже пиши сюда и бери путь из `data_paths.py`.
  - При первом обращении `data_paths.ensure_bot_data()` копирует туда старые `stats.json`, `profile.yml.bak`, `rules/*.yml`
    и `logs/battle_log*` (если копии ещё нет; историю — один раз, метка `bot_data/.history_copied`). Старые файлы не удаляются.

## Что лежит в `logs/`
- **`logs/*.jsonl`** — история боёв. С задачи 2 её пишет бот в `bot_data/logs/`, а в `logs/` лежат только те файлы,
  которые пользователь перенёс сам (например, в `logs/session_XX/`). Старые файлы, созданные ботом до задачи 2, тоже ещё тут.
  - Одна строка — один бой: точное время (`timestamp`), комната, враги, пак,
    результат (`SUCCESS` или `ROLLBACK`), причина, ХП и энергия титанов.
  - Имя файла — время запуска бота.
  - Рядом лежит `battle_log.csv` — короткая версия по всем запускам.
- **`logs/session_XX/observations.txt`** — замечания пользователя во время игры.
  - Вверху дата и время начала сессии. По ним найди бои этой сессии в `.jsonl`.
  - Номер комнаты в замечаниях — число из строки `[СТАТИСТИКА] Комнат: N`, которое пользователь видел последним.
    Значит, ошибка случилась после этой строки в логе (плюс-минус одна комната).
  - Замечания надиктованы голосом, номера иногда расслышаны неточно.
- **`logs/session_XX/log.txt`** (может называться `gui_log_<дата>.txt`) — полный лог из окна бота.
  - В старых логах времени нет. С задачи 1 каждая строка начинается с `ЧЧ:ММ:СС.ммм`. Комнаты разделяются строками `[СТАТИСТИКА] Комнат: N`.
  - В одном логе может быть несколько запусков бота. Каждый начинается строкой
    `[АНАЛИТИКА] Логи сессии будут сохранены в: bot_data/logs/battle_log_<время>.jsonl` (в старых логах — `logs/battle_log_...`), и счёт комнат идёт заново.
  - Лог длинный: **целиком не читай**. Ищи нужные места поиском (`grep -n`) или напиши маленький скрипт.
    Как это делалось — в `docs/analysis_session_01-02.md`.
- **`logs/session_XX/screens/`** — скриншоты пользователя, в имени файла номер комнаты.
- Папка может называться по нескольким сессиям (например `session_01-02`). Тогда ориентируйся на большую сессию.

## Как устроен бот

### Два процесса
1. **`gui.py`** — окно программы (библиотека customtkinter).
   - Кнопка «1. Подключить телефон» запускает scrcpy (`environment.py`).
   - Кнопка «2. Начать фарм» подгоняет окно scrcpy под 1606×748 и запускает бота отдельным процессом:
     `python -X utf8 -u main.py`. В собранном .exe вместо этого `<exe> --bot-mode`.
   - Язык игры передаётся боту через переменную окружения `HEROWARS_LANG`.
2. **`main.py`** — сам бот.
   - Всё, что он печатает (`print`), GUI показывает в чёрном окне лога (`ui/dashboard.py:327-384`).
   - Каждая строка начинается со времени (`14:03:21.457 [НАВИГАЦИЯ] ...`). Бот сам пишет копию лога построчно в
     `bot_data/logs/bot_log_<дата>_<время>.txt` (кнопка «Сохранить лог» по-прежнему работает, но она не нужна).
   - Замеры (`session_log.py`): после каждой комнаты строка `[ВРЕМЯ] Комната N (стихия): коридор | сборка | бой | результат | всего`,
     те же числа в `bot_data/logs/timings_<дата>_<время>.csv`. При остановке — блок `[ИТОГ]`.
     Перед окном SOS печатается `[SOS] Причина: ...`.
   - Этапы: коридор — от закрытия окна результата до экрана выбора команды; сборка — до нажатия «Авто»/«В бой»;
     бой — до кнопки «ОК»; результат — до закрытия окна; откат — отдельно. Точка сохранения и ожидание вашего решения
     считаются отдельно и в «всего» не входят (`ROOM_TIMER.excluded(...)`).
   - Новые замеры или счётчики добавляй через `session_log` (`count`, `excluded`, `ROOM_TIMER.begin`), а не новым `print`-кодом.

### Связь GUI и бота — не ломать, пока `ui/` не трогаем
- **Бот → GUI:** строка с `[SOS_TRIGGER]`, после неё JSON:
  - `{"titans": {...}, "is_manual": ...}` — плохой бой, окно «Требуется вмешательство»;
  - `{"type": "NO_VALID_TEAM", ...}` — правила не дают подходящего пака;
  - `TEST_SUCCESS:{...}` — тестовый пак выиграл, нужно подтверждение.
- GUI ищет эти строки через `in` (`ui/dashboard.py:341-374`). Время в начале строки допустимо,
  а сам маркер и JSON после него менять нельзя.
- Строка с `[ПАУЗА ОТЛАДКИ]` включает в GUI кнопку «Продолжить».
- **GUI → бот:** одна строка в stdin: `IGNORE`, `MANUAL`, `STOP`, `ROLLBACK:титан1,титан2,...`,
  `ROLLBACK_TG:...` (из Telegram), `CONFIRM`, `NEW_PACK:...`.
  «Пройти руками» (в окне и в Telegram) с задачи 8 шлёт `MANUAL`, а не выключает бота (`ui/dashboard.py`, правка разрешена пользователем).
- **Мягкая пауза** — файл `pause.flag` в папке бота. Его создаёт GUI, а при сбое отката — сам бот.
  Пока файл есть, бот ждёт в коридоре.
- **Горячие клавиши** (`main.py:69-90`): Ctrl+Q — остановиться после текущего боя; Ctrl+Shift+Q — остановиться сразу.

### Цикл одной комнаты (машина состояний в `main.py`)
Порядок состояний: `HALLWAY` → `ROOM_SELECTION` → `SET_TEAM` → `PREP_AUTO` или `PREP_SPECIAL_ANGUS` → `WAIT_FOR_OK` → снова `HALLWAY`.

1. **HALLWAY** (`navigation.py`). Ищет кнопку «Атаковать», флажок двери или точку сохранения.
   - Флажок → нажать на дверь.
   - Точка сохранения (конец этажа) → «Активировать» → «Забрать» → ожидание появления флажка двери (не дольше 12 с).
2. **ROOM_SELECTION** (`combat.py:find_smart_door`).
   - Находит кнопки «Атаковать» и по иконке определяет стихию двери (water / mix / earth / fire).
   - Пишет в лог все двери (`[НАВИГАЦИЯ] Двери (слева направо): ...`).
   - Выбирает дверь по порядку `door_order` из профиля (по умолчанию вода → микс → земля → огонь), с учётом правил `skip`
     (`tactics.pick_door`).
   - Распознаёт врагов (`analyzer.py:scan_enemy_team`) и жмёт «Атаковать».
3. **SET_TEAM**. Ждёт экран выбора команды и спрашивает у движка правил, какой пак ставить (`engine.battle_decision`:
   пак и условие правила, которое его дало — оно нужно для обучения).
   - После отката здесь ставится проверяемый пак (`PENDING_RULE`: ваш из окна SOS или запасной, который выбрал бот).
     Запасной пак бота ставится, только если стихия и враги те же, что в комнате с откатом.
   - Если бот решает сам (`auto_rollback`) и в прошлый раз этот пак проиграл этим врагам (бой откатили), сразу ставится
     запасной (`HISTORY.last_failed`).
   - Если этот пак уже стоял в этой стихии в текущем запуске (`LAST_USED_TEAMS`), сборку пропускает.
   - Иначе `team_manager.py:verify_and_set_team`: один снимок нижних слотов; совпало — ничего не нажимает. Не совпало — убирает лишних (справа налево) и ставит нужных по одному снимку, без свайпов «вверх»; ждёт, пока иконки встанут в слоты (до 2 с).
   - Запомненные составы (`LAST_USED_TEAMS`) сбрасываются после мягкой паузы и после ручного боя из SOS — тогда слоты проверятся заново.
4. **PREP_AUTO** — жмёт «Авто», бой идёт в автобое.
   **PREP_SPECIAL_ANGUS** — если в паке Ангус и включён ручной контроль: жмёт «В бой», включает автобой
   на 1,8 с для ульты Ангуса и выключает его (`combat.py:execute_angus_ult`).
5. **WAIT_FOR_OK**. Ждёт кнопку «ОК» окна результата, потом ещё 1,5 с, затем читает ХП и энергию по полоскам
   (`analyzer.py:scan_team_health`) и проверяет пороги и правила.
   - Если не найден хотя бы один титан пака (ищутся только те, кого бот поставил), бот сканирует снова (до 3 раз через 0,5 с, `result_scan.py`). Мёртвый титан находится по иконке (ХП 0) и даёт обычный SOS. Не нашлись и после этого — комната не засчитывается, окно SOS с причиной «Не удалось прочитать окно результата».
   - **Всё хорошо:** пишет бой в историю и статистику, печатает `[СТАТИСТИКА] Комнат: N`, жмёт «ОК».
   - **Плохо:** печатает `[SOS_TRIGGER]` и ждёт решения.
   - **Решение «Пройти руками»** (`MANUAL`, и в окне SOS, и в окне «Нет подходящего пака»): бот ничего не нажимает
     (`main.py:play_manually`, логика `stuck_guard.ManualPlay`) и ждёт, пока коридор виден 2 с подряд. Последним перед коридором
     было окно результата — комната засчитывается; бой или выбор команды (отступили) — нет. Закрыли окно «ОК» без
     переигровки — ХП с окна запоминаются, иначе `GLOBAL_TITAN_STATE` очищается. `LAST_USED_TEAMS` сбрасывается. Дальше бот продолжает сам.
   - **Бот решает сам** (задача 9, `auto_rollback: true` в профиле, по умолчанию выключено): при плохом бое бот без окна SOS
     откатывает бой и переигрывает запасным паком (`tactics.choose_backup`). Не больше `auto_rollback_tries` (1) раз за комнату.
     Не откатывает сам, если бой шёл вручную (Ангус), окно результата не прочиталось или пак выбрали вы — тогда окно SOS.
     Запасной пак: сначала ваш список `backup_teams`, потом паки из правил стихии (анти-паки против этих врагов → паки, уже
     побеждавшие этих врагов → остальные), в последнюю очередь — история боёв. Не берутся паки, проигравшие в этой комнате
     или в прошлый раз этим врагам, с титанами из `skip` или ниже порога паники. Запасной справился — правило запоминается само.
     В логе строки `[ТАКТИКА]`, в `[ИТОГ]` счётчик «из них без вас».
   - **Решение «откат»:** `main.py:run_rollback` → `combat.py:execute_rollback` → шаги в `rollback_logic.py:retreat_from_battle`.
     «Ещё раз» → ждём кнопку паузы до 60 с (загрузка бывает 20–30 с и дольше) → пауза **один раз** → ждём «Отступить» 3 с
     (нет, а пауза видна — жмём снова) → «Отступить» → ждём коридор 15 с. «Отступить» проверяется раньше паузы:
     пока меню паузы открыто, кнопка паузы тоже видна, и по ней жать нельзя. Все шаги в логе с тегом `[ОТКАТ]`.
     Новый пак проверяется в той же комнате. После подтверждения сохраняется правило (`rules_engine.py:learn_new_rule`).
   - **Как запоминается правило** (`learn_new_rule`): всегда «против этих врагов» (`enemies_contain`) плюс условие правила,
     чей пак проиграл (например, `araji < 50`). Название: «Анти-пак против: ... (при Араджи < 50% ХП)». Правило с тем же
     условием не дублируется, а обновляется и поднимается на 1-е место. Свой допуск (`allowed_delta`) — только если удачный бой
     потерял больше общего допуска. Без врагов правило не сохраняется.
   - **Откат не удался** (паузы нет 60 с, «Отступить» не появилась, коридор не виден, ручной бой успел закончиться и «Ещё раз» нет):
     `main.py:handle_rollback_failure` шлёт в Telegram текст со скриншотом (`telegram_agent.send_alert`, если Telegram включён в `profile.yml`),
     создаёт `pause.flag`. После снятия паузы умный старт закроет окно результата без «Ещё раз» кнопкой «ОК».
     Окно «Требуется вмешательство» для этого не используется: оно в `ui/`.
6. Перед каждой дверью бот проверяет лимиты сессии: время, комнаты, этажи, титанит (`main.py:get_stop_reason`).

### Защита от зависаний (`stuck_guard.py`, задача 8)
- **Пределы по состояниям** (`stuck_guard.StateClock`, `STATE_LIMITS_S`): экран выбора команды не появился за 30 с (`SET_TEAM`),
  окно результата не появилось за 3 мин (`WAIT_FOR_OK`). Тогда строка `[СТОРОЖ] Зависание: ...`, скриншот `stuck_...png`, умный старт.
- **Сторож** (`stuck_guard.Watchdog`): 5 мин без пройденной комнаты → `[СТОРОЖ] Бот 5 мин не прошёл ни одной комнаты ...`,
  скриншот, сообщение в Telegram (`send_alert`), умный старт. Третья тревога подряд → мягкая пауза (`pause.flag`).
  Комната (`count_cleared_room`) и снятие паузы сбрасывают тревоги.
- Время ожидания вас (окно SOS, мягкая пауза, ручное прохождение, окно игры не в фокусе) сторож и пределы не считают:
  `main.py:user_waited()` (вызывается в `wait_for_input`, `wait_for_focus`, `play_manually`, после паузы). Новые ожидания человека — тоже через неё.
- Ещё защиты: если виден флажок двери, бот из `SET_TEAM`/`PREP_*`/`WAIT_FOR_OK` возвращается в коридор; после таймаута коридора
  экран выбора команды ведёт в `SET_TEAM`, окно результата — в `WAIT_FOR_OK`.
- **ПК заблокирован (Win+L):** Windows не даёт делать снимки, `mss` падает с `ScreenShotError: ... BitBlt`. Все снимки бота идут
  через `vision.grab_frame` (не вызывай `sct.grab` напрямую): при этой ошибке бот не падает, а пробует снова раз в 2 с
  (`stuck_guard.grab_or_wait`). В логе `[ЭКРАН] Не удаётся сделать снимок экрана ...` и `[ЭКРАН] Снимок экрана снова работает (ждали N с)`.
  Дольше минуты — одно сообщение в Telegram (`main.py:alert_screen_locked`). Время ожидания — отдельный счётчик «экран заблокирован»
  (`screen_lock`, столбец `screen_lock_s` в CSV), сторож его не считает.
- Ошибка Python: `session_log` печатает ошибку, `atexit` — `[ИТОГ]`, затем `alert_on_crash` шлёт сообщение в Telegram.
- Счётчик «зависания» (`stuck`) — в `[ИТОГ]` и в `timings_*.csv`.

### Как бот выбирает пак (`rules_engine.py`, `bot_data/rules/*.yml`, `profile.yml`)
- Для каждой стихии есть файл `bot_data/rules/<стихия>.yml` (рабочая копия; при первом запуске копируется из `rules/`):
  базовый пак `default_team` и список правил `rules`.
- **Порядок проверки:**
  1. правила `action: skip` — дают «чёрный список» титанов и запрещают двери;
  2. правила спасения (`titan_hp_below`, `titan_energy_below`);
  3. анти-паки (`enemies_contain`);
  4. базовый пак.

  Внутри группы правила проверяются сверху вниз.
- **Особые значения:**
  - пак `[STOP]` — остановиться и спросить;
  - `require_fought` — титан уже должен был провести бой в этом запуске;
  - `allowed_delta` — свой допуск потерь;
  - `special_ult: angus`.
- **Пороги** из `profile.yml` (все читает `tactics.Settings`): `critical_hp` (порог паники, %), `max_hp_delta` (допуск потерь
  за бой, %), `group_loss_titans`/`group_loss_percent` (общие потери пака, по умолчанию 3 титана по 40%, 0 — выключено),
  `titan_critical_hp` (личные пороги паники `{титан: %}`, по желанию). Настройки бота «решает сам»: `auto_rollback`,
  `auto_rollback_tries`, `backup_teams`, `door_order` (пример — `profile.example.yml`). GUI их не показывает, но и не стирает.
  Бой считается плохим (`battle_verdict.py:evaluate_battle`, вызывается из `main.py` в `WAIT_FOR_OK`), если:
  кто-то умер или его иконка не найдена, у кого-то ХП ниже порога паники (личного или общего), кто-то потерял больше допуска,
  N титанов и больше потеряли по X% (общие потери),
  либо правило отхила (`titan_hp_below`) сработало *из-за этого боя* (до боя нет, после есть, у титана, который дрался).
  Движок правил после боя заново **не** спрашивается. Правила по энергии и `skip` на итог боя не влияют — они работают перед следующим боем.
- **Состояние титанов** (`GLOBAL_TITAN_STATE`: ХП и энергия после последнего боя) — `titan_state.TitanMemory`: сохраняется
  в `bot_data/titan_state.json` при каждом `update`/`clear` и загружается при запуске, если игровой день тот же
  (`stats_manager.get_game_date`, `reset_hour`). В новый игровой день (в коридоре) очищается. Очищается и после мягкой паузы
  и ручного боя (ХП бот не видел). Если вы играли руками между запусками бота, цифры в файле могут быть неточными.
- **История боёв для тактики** (`tactics.BattleHistory`): при запуске читается `bot_data/logs/*.jsonl`, новые бои
  добавляются через `main.py:record_battle` (`analytics.log_battle` возвращает запись).
- Правила читаются один раз при запуске. Если поменять их в GUI во время работы, бот этого не увидит.

### Как бот видит и нажимает (`vision.py`)
- Снимок окна scrcpy делается через `mss` (`vision.grab_frame`; при заблокированном ПК ждёт разблокировки).
  В первый раз бот находит в окне область игры без рамок и чёрных полос и считает масштаб от высоты 720 (`_calibrate_geometry`).
  Эталонный размер окна — 1606×748, масштаб около 0,978.
- Шаблон берётся из `assets/<ЯЗЫК>/имя.png`, если такой есть, иначе из `assets/имя.png`, и масштабируется.
- Пороги совпадения: обычно 0,75–0,8; титаны в слотах — 0,88; враги — 0,72; иконки на окне результата — 0,62.
- Каждый вызов `get_match_loc` делает **новый снимок экрана**. `get_first_match` ищет сразу несколько картинок на одном снимке (так работает откат).
- **Нажатие.** Координаты переводятся в пиксели телефона (`adb shell wm size`) и отправляются через
  `subprocess.Popen(["adb", "shell", "input", "tap", ...])`. `click_human` возвращает этот процесс.
  Бот сам нажатие не ждёт, но по процессу знает, когда команда дошла до телефона (`click_logic.TapWatch`).
  Задержка нажатия измеряется в `[ИТОГ]` (строка «Нажатия adb tap»).
  Точка нажатия случайная внутри кнопки (по 20% от краёв не трогает). Для двери — случайная точка в центральной половине зоны под флажком
  (`click_logic.door_click_zone`).
- **Повторное нажатие** (`vision.find_and_click_bulletproof`, правило в `click_logic.RetryPolicy`): бот жмёт кнопку один раз
  и ждёт, пока она пропадёт. Жмёт снова, только если через 4 с **после того, как команда дошла до телефона** экран не отреагировал
  (после нажатия окно часто «думает» — затемнение и кружок загрузки, ~3 с; при 1,5 с бот жал во время загрузки).
  Если кнопка бледнеет или сдвигается (окно закрывается), ждёт дольше, но не больше 8 с.
  Так же работает «Атаковать» в `combat.find_smart_door`. В логе повтор виден строкой `Клик по '...' не зарегистрирован сервером`.
- **Дверь** (`navigation.smart_navigate_hallway`): бот жмёт, только когда флажок стоит на месте
  (3 снимка подряд в одной точке ±3 пикселя, не меньше 0,2 с; если не встал за 3 с — жмёт как есть).
  Если окно «Атаковать» не открылось за 2 с после того, как нажатие дошло до телефона, — это промах (`door_misses`),
  бот сразу смотрит флажок заново.
- **Переход на новый этаж:** после «Забрать» бот ждёт, пока появится флажок двери (`navigation.wait_for_new_floor`, не дольше 12 с).
  Спуск идёт ~8–10 с, и всё это время «Активировать» ещё виден, поэтому раньше в коридор возвращаться нельзя.
  Строка в логе: `На новом этаже появилась дверь через N с после награды`. Ожидание «картинка замерла» пробовали в задаче 4,
  но на фоне всегда что-то шевелится (10 раз из 10 не сработало), его убрали.
- **Начало боя** (`main.py`, `PREP_AUTO`): «Авто» жмётся через `find_and_click_bulletproof`, то есть с проверкой и повтором.
  Если боя нет через 10 с, а на экране всё ещё выбор команды, бот возвращается в `SET_TEAM` и жмёт снова (до 3 раз подряд),
  потом останавливается с причиной «Не удалось начать бой». Решение в `click_logic.after_failed_battle_start`
  (`main.py:handle_failed_start`). Так же с «В бой» для Ангуса: если она не нажалась.
  Если бот в состоянии `HALLWAY`, а на экране выбор команды (таймаут коридора 10 с), он возвращается в `SET_TEAM`;
  если на экране окно результата («ОК») — в `WAIT_FOR_OK` (бой закончился позже, чем бот его ждал; сессия 06).
- **Задержка нажатия.** По замеру сессии 05 (`[ИТОГ]`) одно `adb tap` занимает в среднем 0,42 с, максимум 3,2 с.
  В строке «не зарегистрирован сервером» теперь пишется, сколько секунд выполнялось нажатие, а в следующей строке — через сколько
  после повтора кнопка пропала. По ним видно, теряются ли нажатия или окно просто медленно закрывается.
- **Свайп** — `adb shell input swipe` (0,4 с), после него пауза 0,6 с.

## Как запустить бота на ПК пользователя (Windows)

### Один раз
1. Python 3.11 или новее с python.org. При установке поставить галочку «Add python.exe to PATH».
   Библиотеки в `requirements.txt` свежие: numpy 2.5 на Python 3.10 не ставится, хотя README пишет «3.10+».
2. scrcpy (в комплекте есть adb). Распаковать и добавить папку в PATH.
   Проверка в cmd: `adb devices` показывает телефон со статусом `device`; `scrcpy --version` работает.
3. На телефоне включить «Отладка по USB» и «Отладка по USB (настройки безопасности)». Без второго пункта нажатия не работают.

### Обычный запуск
1. Запускать всегда **из папки проекта**: пути к `profile.yml`, `rules/`, `bot_data/` относительные.
2. Двойной клик по `start.bat`. В первый раз он создаст `venv` и поставит библиотеки (несколько минут), потом откроет окно программы.
   То же самое вручную в cmd из папки проекта:
   ```
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   python gui.py
   ```
3. В окне программы:
   1. «1. Подключить телефон» — появится окно `HeroWarsBot_Arena`;
   2. в игре зайти в подземелье и встать в коридоре;
   3. «2. Начать фарм».
4. Если после обновления кода поменялся `requirements.txt`, ещё раз выполнить `venv\Scripts\activate` и `pip install -r requirements.txt`.

### Запуск бота без окна программы (для отладки)
```
scrcpy --window-title HeroWarsBot_Arena --stay-awake
```
Во втором окне cmd из папки проекта:
```
venv\Scripts\activate
set HEROWARS_LANG=RU
python -X utf8 -u main.py
```
- Ответ на окно SOS печатается прямо в это окно: `IGNORE`, `STOP`, `MANUAL`, `ROLLBACK:hyperion,sigurd,tidus,nova,mairi`, `CONFIRM`.
- Размер окна scrcpy так не подгоняется, а он должен быть около 1606×748. Проще запускать через GUI (там есть кнопка «Сброс размера»).

## Как проверять без игры (тесты в облаке)
Установка и запуск (проверено, в облаке ставится):
```
pip install pyyaml numpy opencv-python-headless pytest
python -m pytest -q
```

Тесты кладём в папку `tests/` (сейчас там `test_session_log.py` — время в строках, этапы, итог, CSV, лог в файл; `test_data_paths.py` — переезд файлов в `bot_data/`; `test_battle_verdict.py` — оценка боя; `test_click_logic.py` — повторные нажатия, дверь, переход на этаж, начало боя, «Атаковать» на подделке экрана и часов; `test_rollback.py` — откат боя на подделке игры и `send_alert`; `test_result_scan.py` — чтение окна результата на `54.png`/`111.png` и пересканирование; `test_team_manager.py` — слоты состава на `pered_boem.png`; `test_stuck_guard.py` — сторож и пределы на поддельных часах, «Пройти руками», итог при ошибке Python, ожидание при заблокированном ПК;
`test_tactics.py` — настройки тактики, история, запасной пак, выбор двери, запоминание правил; `test_titan_state.py` — файл состояния титанов;
`test_replay_session_b.py` — «повтор» всей сессии B по `tests/data/session_B.jsonl` (копия истории боёв 18.10.2026 из git)). Ограничения:
- **`main.py` запускает бота прямо при импорте** (цикл `while True` на уровне модуля), поэтому импортировать его в тестах нельзя.
  Логику, которую надо проверить, выносим в отдельные функции или модули.
- **`pygetwindow` на Linux падает уже при импорте.** Поэтому `vision.py`, `analyzer.py`, `navigation.py`,
  `combat.py`, `team_manager.py`, `environment.py` в облаке без заглушки не импортируются.
  В тесте до импорта: `sys.modules["pygetwindow"] = types.ModuleType("pygetwindow")`.
  `ctypes.windll` (горячие клавиши) есть только в Windows.
- **`rules_engine.py` при импорте читает** `profile.yml` и `rules/*.yml` из текущей папки (`engine = RulesEngine()`).
  В тестах переходи во временную папку (`monkeypatch.chdir(tmp_path)`) и создавай `RulesEngine()` там.
- **`analytics.py` при импорте удаляет лишние старые файлы в `bot_data/logs/`** и создаёт эту папку. Импортируй его только после
  `monkeypatch.chdir(tmp_path)` (и удали из `sys.modules`, если он уже импортирован) — пример в `tests/test_data_paths.py`.
- **`data_paths.ensure_bot_data()` помнит папку, которую уже проверил.** В тестах перед каждым тестом очищай `data_paths._CHECKED`.
- Распознавание можно проверять на скриншотах пользователя (`logs/session_*/screens/`) и шаблонах из `assets/`:
  `cv2.imread` работает и в облаке. Например, на `54.png` и `111.png` видно окно результата, а в логе есть правильные ХП
  (54: Араджи 100, Гиперион 100, Ригель 55, Ияри 100, Люмира 100; 111: 56, 59, 81, 38, 44).
- История боёв (`logs/*.jsonl`, а в новых сессиях `bot_data/logs/*.jsonl`) и логи сессий можно разбирать скриптами — так удобно проверять новую логику на настоящих данных.

## Правила работы
1. **Одна задача — одна сессия.** Меняй только файлы, нужные для этой задачи.
   Задачи берём из `PLAN.md` по порядку, если пользователь не сказал иначе.
2. **Если логику можно проверить без игры — пиши тесты и запускай их.** В отчёте пиши, какие тесты прошли.
3. **В конце каждой сессии напиши пользователю по-русски простыми словами:**
   - что изменил;
   - зачем;
   - как проверить в игре: по шагам, что запустить и на какие строки лога смотреть;
   - что он должен сделать руками (например, добавить картинку, поменять настройку, удалить или перенести файл).
4. Бота в облаке не запускать. Большие логи целиком не читать.
5. Не ломать связь GUI и бота (`[SOS_TRIGGER]`, команды через stdin, `pause.flag`), пока `ui/` не трогаем.
6. **Действия должны оставаться человеческими:** случайная точка нажатия, пауза реакции, никаких серий быстрых нажатий.
   Ускоряем бота, убирая лишние ожидания, повторы и проверки, а не делая нажатия быстрее человека.
7. Не коммить `profile.yml`, токены и chat_id. Файлы, которые бот пишет на ПК, — в `bot_data/` (она в `.gitignore`), не в `logs/`; путь бери из `data_paths.py`.
8. **Пиши код как в остальном проекте:** комментарии и сообщения лога по-русски,
   сообщения лога с тегом в квадратных скобках (`[НАВИГАЦИЯ] ...`, `[КОМАНДА] ...`).
9. Сделал задачу — отметь её в `PLAN.md`. Поменялось устройство бота — обнови этот файл.
10. Ничего не удаляй и не переименовывай из файлов пользователя (`logs/`, `rules/`, `stats.json`, `bot_data/`, `profile.yml`) без его согласия.
