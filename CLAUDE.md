# CLAUDE.md — памятка для работы над HeroWarsBot

## Кто пользователь и как с ним говорить
- Пользователь не программист, пишет код с помощью ИИ.
- Объясняй простым языком, как старшекласснику. Пиши по-русски.
- Термины расшифровывай, а вместо длинных рассуждений давай короткие шаги.

## О проекте: главные факты
- Бот для Hero Wars на Python. Он проходит подземелье титанами.
- Игра идёт на Android-телефоне, подключённом к ПК (Windows) по USB.
- Экран телефона показывается в окне scrcpy с заголовком `HeroWarsBot_Arena`.
- Бот делает снимки этого окна (`mss`), ищет на них картинки-шаблоны через OpenCV (`cv2.matchTemplate`)
  и нажимает на телефоне через ADB (`adb shell input tap` / `swipe`).
- **Запустить бота здесь, в облаке, нельзя:** нет телефона, игры и scrcpy. Не пытайся. Проверяет пользователь сам у себя на ПК.
- **Картинки.** Полный набор — папка `assets/`, она есть в репозитории.
  - Файла с картинками в base64 (`assets_db.py`) сейчас в репозитории нет: его удалили 13.09.2026, он остался только в истории git.
  - На ПК пользователя его тоже нет: в логе строка «Файл assets_db.py не найден. Использую чтение с диска».
  - Если этот файл появится, бот будет брать картинки из него, а не из `assets/` (`vision.py:15-22`, `vision.py:146-163`).
    Тогда после замены картинки в `assets/` его нужно пересобрать или удалить.
- **`assets/` есть в `.gitignore`.** Картинки, которые уже в репозитории, git продолжает отслеживать.
  Новую картинку git не увидит — добавлять так: `git add -f assets/имя.png`.
- Если нужно знать, какие картинки есть, или нужны конкретные иконки — попроси пользователя, он пришлёт.
  Пиши точное имя файла и что на картинке должно быть.
- **`ui/`** — графическая оболочка. Пока её не трогаем. Исключение — если задача или пользователь прямо разрешили.
  Разрешено: «Пройти руками» (задача 8), настройки тактики (задача 9: переключатель «Бот решает сам» и окно «⚙️ Тактика»),
  закрытие окна SOS, когда бот решил сам (задача 9б: строка `[SOS_CLOSE]` в `ui/dashboard.py`).
  Задача 15 (новый дизайн): `ui/` переделываем целиком, по шагам и правилам ниже.
- Новый дизайн интерфейса лежит в design/README.md. При работе с интерфейсом сверяйся с ним и с картинками в design/screenshots.
- **Задача 15 — новый дизайн, идёт по шагам** (`PLAN.md`, «План по шагам»): после каждого шага остановка и проверка пользователем.
  Новое окно собирается рядом со старым, старые файлы `ui/` не удаляются, пока новое не умеет всё.
  - **Макеты рисовали по описанию, вслепую.** Что умеет окно — решают старое окно и бот, как выглядит — макеты.
    Перед каждым шагом сверь экран по `docs/ui_inventory.md` (старое окно ↔ макет ↔ бот). Нашёл расхождение (в макете нет старой функции,
    в макете функция, которой нет в боте, макет спорит с логикой) — **не решай сам**: допиши в сверку и спроси пользователя,
    с вариантами и своей рекомендацией. Старые функции молча не выкидывай, логику в бота без разрешения не добавляй.
  - **Связь окна и бота не ломать** (раздел «Связь GUI и бота» и `docs/ui_inventory.md`, раздел 0): те же строки бота и те же команды.
    Новая кнопка шлёт ту же команду, что старая. С шага 3 тест на поддельном боте (`tests/test_bot_link.py`) — прогонять на каждом шаге.
  - **Окна без макета** (окна вмешательства, Telegram, проверка пака) рисуй из общих виджетов в стиле макетов и сначала покажи скриншот.
  - **Новая библиотека** — только с согласия пользователя, сразу в `requirements.txt` с версией, а в отчёте — как поставить
    (`venv\Scripts\activate`, `pip install -r requirements.txt`): `start.bat` ставит библиотеки только при первом запуске.
  - Основа (шаг 1): `ui/theme.py` — все цвета, шрифты, размеры (hex только здесь; тест `test_no_hex_outside_theme`),
    `ui/icons/` — иконки (`icon(имя, цвет, размер)`), `ui/widgets.py` — общие виджеты, витрина `python -m ui.demo`.
  - Титаны в интерфейсе — внутренними именами (`araji`), имя на языке окна — `i18n` `titan_<имя>`. Названия из `i18n.py` с эмодзи
    («🌿 Земля») — через `theme.plain_text`: в новом окне эмодзи нет.
  - Картинки титанов для окна — `assets/icons/<титан>.png` (`theme.titan_icon_path`), бот их не читает. Нет картинки — две буквы имени.
    Пользователь рисует их без обводки и любого размера: обводку цветом стихии и уменьшение делает программа; в `.exe` — из `assets_db.py` (шаг 8).
  - В подклассах виджетов CustomTkinter не называй свои методы и поля `_draw`, `_image`, `_text`, `_hover`, `_on_enter`, `_on_leave`:
    они уже есть внутри CustomTkinter (на этом падало).
- **Пользователь и игроки — не программисты: все настройки должны задаваться в окне программы.**
  Не проси править `profile.yml` или другие файлы руками.
- **`logs/`** заполняет сам пользователь. Бот и окно программы в неё больше ничего не пишут и ничего в ней не удаляют.
- **`bot_data/`** (в `.gitignore`) — всё, что бот и окно программы пишут сами. Пути прописаны в `data_paths.py`:
  - `bot_data/stats.json` — статистика;
  - `bot_data/rules/*.yml` — рабочие правила (`rules/` в репозитории — правила по умолчанию, бот туда не пишет);
  - `bot_data/logs/` — история боёв (`battle_log_*.jsonl`, `battle_log.csv`), лог бота (`bot_log_*.txt`), замеры (`timings_*.csv`);
  - `bot_data/profile.yml.bak` — копия профиля (там токен Telegram);
  - `bot_data/titan_state.json` — ХП и энергия титанов после последнего боя, в пределах игрового дня (`titan_state.py`);
  - `bot_data/temp_sos.png`, `bot_data/temp_test.png` — скриншоты для Telegram.
  - `bot_data/sos_info.json` — комната, враги, причина и пак последнего окна SOS (задача 13): бот пишет перед `[SOS_TRIGGER]`,
    окно программы берёт для сообщения в Telegram (старше 2 мин — не берёт).
  - `bot_data/debug/` — скриншоты для разбора: `sos_комната<N>_<стихия>_<время>.png` при каждом SOS, `result_unreadable_...png`, если окно результата не прочиталось, и `stuck_...png` при зависании (сторож, задача 8). С задачи 14 бот оставляет 50 новых и удаляет остальные.
    Задача 8б (обрыв связи): `rollback_wait_...png` — откат начал ждать игру (экран не узнаётся), `rollback_fail_...png` — откат не удался,
    `start_fail_...png` — бой так и не начался после медленных попыток.
  - Новые файлы бота тоже пиши сюда и бери путь из `data_paths.py`.
  - При первом обращении `data_paths.ensure_bot_data()` копирует туда старые `stats.json`, `profile.yml.bak`, `rules/*.yml`
    и `logs/battle_log*` (если копии ещё нет; историю — один раз, метка `bot_data/.history_copied`). Старые файлы не удаляются.

## Что лежит в `logs/`
- **С задачи 14 `logs/` нет в репозитории** (она в `.gitignore`): у пользователя она остаётся на ПК, он присылает логи сессий для разбора.
  Тесты на `logs/` больше не опираются: нужные скриншоты и лог лежат в `tests/data/` (`screens/*.webp` — те же пиксели, `session_07_bot_log.txt`).
- **`logs/*.jsonl`** — история боёв. С задачи 2 её пишет бот в `bot_data/logs/`, а в `logs/` лежат только те файлы,
  которые пользователь перенёс сам (например, в `logs/session_XX/`). Старые файлы, созданные ботом до задачи 2, тоже ещё тут.
  - Одна строка — один бой: точное время (`timestamp`), комната, враги, пак,
    результат (`SUCCESS` или `ROLLBACK`), причина, ХП и энергия титанов.
  - Имя файла — время запуска бота.
  - Рядом лежит `battle_log.csv` — короткая версия по всем запускам.
- **`logs/session_XX/observations.txt`** — замечания пользователя во время игры.
  - Вверху дата и время начала сессии. По ним найди бои этой сессии в `.jsonl`.
  - Номер комнаты в замечаниях — число из строки `[СТАТИСТИКА] Комнат: N`, которое пользователь видел последним.
    Значит, ошибка случилась после этой строки в логе (плюс-минус одна комната).
  - Замечания надиктованы голосом, номера иногда расслышаны неточно.
- **`logs/session_XX/log.txt`** (может называться `gui_log_<дата>.txt`) — полный лог из окна бота.
  - В старых логах времени нет. С задачи 1 каждая строка начинается с `ЧЧ:ММ:СС.ммм`. Комнаты разделяются строками `[СТАТИСТИКА] Комнат: N`.
  - В одном логе может быть несколько запусков бота. Каждый начинается строкой
    `[АНАЛИТИКА] Логи сессии будут сохранены в: bot_data/logs/battle_log_<время>.jsonl` (в старых логах — `logs/battle_log_...`), и счёт комнат идёт заново.
  - Лог длинный: **целиком не читай**. Ищи нужные места поиском (`grep -n`) или напиши маленький скрипт.
    Как это делалось — в `docs/analysis_session_01-02.md`.
- **`logs/session_XX/screens/`** — скриншоты пользователя, в имени файла номер комнаты.
- Папка может называться по нескольким сессиям (например `session_01-02`). Тогда ориентируйся на большую сессию.

## Как устроен бот

### Два процесса
1. **`gui.py`** — окно программы (библиотека customtkinter).
   - Кнопка «1. Подключить телефон» запускает scrcpy (`environment.py`).
   - Кнопка «2. Начать фарм» подгоняет окно scrcpy под 1606×748 и запускает бота отдельным процессом:
     `python -X utf8 -u main.py`. В собранном .exe вместо этого `<exe> --bot-mode`.
   - Язык игры передаётся боту через переменную окружения `HEROWARS_LANG`.
2. **`main.py`** — сам бот.
   - Всё, что он печатает (`print`), GUI показывает в чёрном окне лога (`ui/dashboard.py:327-384`).
   - Каждая строка начинается со времени (`14:03:21.457 [НАВИГАЦИЯ] ...`). Бот сам пишет копию лога построчно в
     `bot_data/logs/bot_log_<дата>_<время>.txt` (кнопка «Сохранить лог» по-прежнему работает, но она не нужна).
   - Замеры (`session_log.py`): после каждой комнаты строка `[ВРЕМЯ] Комната N (стихия): коридор | сборка | бой | результат | всего`,
     те же числа в `bot_data/logs/timings_<дата>_<время>.csv`. При остановке — блок `[ИТОГ]`.
     Перед окном SOS печатается `[SOS] Причина: ...`.
   - Этапы: коридор — от закрытия окна результата до экрана выбора команды; сборка — до нажатия «Авто»/«В бой»;
     бой — до кнопки «ОК»; результат — до закрытия окна; откат — отдельно. Точка сохранения и ожидание вашего решения
     считаются отдельно и в «всего» не входят (`ROOM_TIMER.excluded(...)`).
   - Новые замеры или счётчики добавляй через `session_log` (`count`, `excluded`, `ROOM_TIMER.begin`), а не новым `print`-кодом.

### Связь GUI и бота — не ломать, пока `ui/` не трогаем
- **Бот → GUI:** строка с `[SOS_TRIGGER]`, после неё JSON:
  - `{"titans": {...}, "is_manual": ...}` — плохой бой, окно «Требуется вмешательство»;
  - `{"type": "NO_VALID_TEAM", ...}` — правила не дают подходящего пака;
  - `TEST_SUCCESS:{...}` — тестовый пак выиграл, нужно подтверждение.
- GUI ищет эти строки через `in` (`ui/dashboard.py:monitor_bot_output`). Время в начале строки допустимо,
  а сам маркер и JSON после него менять нельзя.
- Строка с `[SOS_CLOSE]` (задача 9б): вы не ответили, бот решил сам. GUI закрывает окна SOS, проверки пака, выбора пака
  и опрос Telegram (`close_sos_windows`), а ответы из старых окон боту не отправляет (`sos_epoch`).
- Строка с `[ПАУЗА ОТЛАДКИ]` включает в GUI кнопку «Продолжить».
- **GUI → бот:** одна строка в stdin: `IGNORE`, `MANUAL`, `STOP`, `ROLLBACK:титан1,титан2,...`,
  `ROLLBACK_TG:...` (из Telegram), `CONFIRM`, `NEW_PACK:...`. Бот помнит время каждой строки: ответ, пришедший раньше,
  чем бот задал вопрос, пропускается (`main.py:wait_for_input(since=...)`, строка `[ЛОГИКА] Пропускаю ответ ...`).
  «Пройти руками» (в окне и в Telegram) с задачи 8 шлёт `MANUAL`, а не выключает бота (`ui/dashboard.py`, правка разрешена пользователем).
- **Мягкая пауза** — файл `pause.flag` в папке бота. Его создаёт GUI, а при сбое отката — сам бот.
  Пока файл есть, бот ждёт в коридоре.
- **Горячие клавиши** (`main.py:69-90`): Ctrl+Q — остановиться после текущего боя; Ctrl+Shift+Q — остановиться сразу.

### Цикл одной комнаты (машина состояний в `main.py`)
Порядок состояний: `HALLWAY` → `ROOM_SELECTION` → `SET_TEAM` → `PREP_AUTO` или `PREP_SPECIAL_ANGUS` → `WAIT_FOR_OK` → снова `HALLWAY`.

1. **HALLWAY** (`navigation.py`). Ищет кнопку «Атаковать», флажок двери или точку сохранения.
   - Флажок → нажать на дверь.
   - Точка сохранения (конец этажа) → «Активировать» → «Забрать» → ожидание появления флажка двери (не дольше 12 с).
     Окно награды ждётся после того, как нажатие «Активировать» дошло (`wait_after_tap`), пауза реакции перед «Забрать» — от его появления.
   - Флажок, «Атаковать» и «Активировать» ищутся на одном снимке (задача 11).
2. **ROOM_SELECTION** (`combat.py:find_smart_door`).
   - Находит кнопки «Атаковать» и по иконке определяет стихию двери (water / mix / earth / fire).
   - Пишет в лог все двери (`[НАВИГАЦИЯ] Двери (слева направо): ...`).
   - Выбирает дверь по порядку `door_order` из профиля (по умолчанию вода → микс → земля → огонь), с учётом правил `skip`
     (`tactics.door_choice`).
   - **По здоровью** (задача 9б, только если бот решает сам; `main.py:door_hints`): если дверей несколько, сначала та,
     где сработает ваше правило отхила (условие по ХП без врагов, в паке есть раненый и лекарь из `tactics.HEALERS`);
     дверь, опасная для раненых по прогнозу (см. SET_TEAM), пропускается, если есть другая. Строка
     `[НАВИГАЦИЯ] Выбрана комната ... по здоровью титанов: ...`.
   - Распознаёт врагов (`analyzer.py:scan_enemy_team`) и жмёт «Атаковать».
3. **SET_TEAM**. Ждёт экран выбора команды и спрашивает у движка правил, какой пак ставить (`engine.battle_decision`:
   пак и условие правила, которое его дало — оно нужно для обучения).
   - **Сначала — точное ХП и энергия** (задача 9в, `main.py:read_team_screen`): один снимок нижних слотов, кто там стоит
     (если бот уже ставил пак в этой стихии — ищет только этих титанов, так быстрее) и полоски под иконками
     (`team_manager.scan_slots` → `analyzer.read_bars_under_icon`). Цифры заменяют память (`GLOBAL_TITAN_STATE`) **до** выбора пака.
     В логе `[СОСТОЯНИЕ] Перед боем (экран выбора команды): ARAJI 36% ⚡47% (бот помнил 55%), ...` — в скобках, если память
     была другой или пустой (`titan_state.screen_reading`). Такие полоски перечитываются через 0,3 с, пока два снимка не совпадут
     (`team_manager.recheck_bars`, вдруг полоски ещё не дорисовались). ХП не прочиталось — память не трогается.
     Тех, кого бот поставил при сборке, читает со снимка, где состав совпал.
   - **Пак отхила по правилам игры** (задача 9в, только если бот решает сам, только в смешанной и только вместо базового пака;
     `tactics.heal_plan`): ваше правило отхила не сработало, а кто-то ниже `heal_below_hp` (по умолчанию 60%), но не ниже
     порога паники и не под запретом skip. Лечим по одному: сначала основных (базовые паки, `tactics.regulars`), потом запасных (`reserve` — ваши запасные паки
     и паки правил, `tactics.own_titans`), внутри — того, кто ближе к своему порогу паники. Титана не из ваших паков и правил
     не лечим (сессия 08: Алекто).
     Титана нет в паке, и в своей комнате его не лечат (в базовом паке его стихии нет лекаря: огненные) — он встаёт
     вместо первого из «кого убирать» (`tactics.removal_order`: ваш список `heal_remove_order`, потом с конца пака, кроме лекарей —
     для вашего пака Амон, потом Люмира). Водных и земляных тянем, только если в своей комнате (`tactics.home_rooms`) они 2 боя подряд не поднимаются выше порога — отхила там не хватает. Раненый уже в паке, но 2 боя
     подряд в смешанной не поднимается выше порога (`BattleHistory.not_healing`) — вместо убранного встаёт здоровый (от 80% ХП)
     и заряженный (от 60% энергии) лекарь из базовых паков, как Сигурд для Ригеля. Пак отхила не собрался (титан не встал

   - Флажок коридора и «ОК» ищутся на одном снимке (`main.py:STATE_BUTTONS`, `vision.find_many`); пока «ОК» нет, бот ждёт 0,1 с.
   - Если не найден хотя бы один титан пака (ищутся только те, кого бот поставил), бот сканирует снова (до 3 раз через 0,5 с, `result_scan.py`).      до `rollback_logic.GAME_WAIT_S` (15 мин от начала отката): строка `[ОТКАТ] Бой не загрузился за 1 мин, экран не узнаю: ... Не сдаюсь`,
     скриншот `rollback_wait_...png`, раз в минуту `Всё ещё жду игру: ...`. Загрузился бой — пауза сразу (экран смотрится раз в 0,25 с)
     и «Отступить», строка `Игра снова откликается (ждал N)`; вернулось окно с «Ещё раз» — жмёт снова, после 2 повторов не чаще раза

     как раньше. Повторное «Ещё раз» запускает 60 с заново. Время ожидания игры сторож не считает (`RollbackResult.game_wait_s`).

     чей пак проиграл (например, `araji < 50`). Название: «Анти-пак против: ... (при Араджи < 50% ХП)». Правило с тем же
     условием не дублируется, а обновляется и поднимается на 1-е место. Свой допуск (`allowed_delta`) — только если удачный бой
     потерял больше общего допуска. Без врагов правило не сохраняется.
   - **Откат не удался** (экран не узнаётся 15 мин, пауза не открывает меню 60 с, «Отступить» не сработала, ручной бой успел закончиться и «Ещё раз» нет):
     `main.py:handle_rollback_failure` сохраняет `bot_data/debug/rollback_fail_...png`, шлёт его в Telegram с текстом

     создаёт `pause.flag`. После снятия паузы умный старт закроет окно результата без «Ещё раз» кнопкой «ОК».
     Окно «Требуется вмешательство» для этого не используется: оно в `ui/`.

### Защита от зависаний (`stuck_guard.py`, задача 8)
- **Пределы по состояниям** (`stuck_guard.StateClock`, `STATE_LIMITS_S`): экран выбора команды не появился за 30 с (`SET_TEAM`),
  окно результата не появилось за 3 мин (`WAIT_FOR_OK`). Тогда строка `[СТОРОЖ] Зависание: ...`, скриншот `stuck_...png`, умный старт.

  скриншот, сообщение в Telegram (`send_alert_in_background`), умный старт. Третья тревога подряд → мягкая пауза (`pause.flag`).
  Комната (`count_cleared_room`) и снятие паузы сбрасывают тревоги.
- Время ожидания вас (окно SOS, мягкая пауза, ручное прохождение, окно игры не в фокусе) сторож и пределы не считают:
  `main.py:user_waited()` (вызывается в `wait_for_input`, `wait_for_focus`, `play_manually`, после паузы). Новые ожидания человека — тоже через неё.
- Ещё защиты: если виден флажок двери, бот из `SET_TEAM`/`PREP_*`/`WAIT_FOR_OK` возвращается в коридор; после таймаута коридора
  экран выбора команды ведёт в `SET_TEAM`, окно результата — в `WAIT_FOR_OK`.
- **ПК заблокирован (Win+L):** Windows не даёт делать снимки, `mss` падает с `ScreenShotError: ... BitBlt`. Все снимки бота идут
  через `vision.grab_frame` (не вызывай `sct.grab` напрямую): при этой ошибке бот не падает, а пробует снова раз в 2 с
  (`stuck_guard.grab_or_wait`). В логе `[ЭКРАН] Не удаётся сделать снимок экрана ...` и `[ЭКРАН] Снимок экрана снова работает (ждали N с)`.
  Дольше минуты — одно сообщение в Telegram (`main.py:alert_screen_locked`). Время ожидания — отдельный счётчик «экран заблокирован»
  (`screen_lock`, столбец `screen_lock_s` в CSV), сторож его не считает.
- Ошибка Python: `session_log` печатает ошибку, `atexit` — `[ИТОГ]`, затем `send_session_report` шлёт итог в Telegram (с ошибкой).
- Счётчик «зависания» (`stuck`) — в `[ИТОГ]` и в `timings_*.csv`. С задачи 9в там же «паки отхила (бот собрал сам)» (`heal_packs`)
  и «ХП поправлено по экрану выбора команды» (`screen_hp`: сколько раз цифры с экрана разошлись с памятью или память была пустой).

  не ушло из-за связи (`NETWORK_ERROR`) — снова через 30 с, 1, 2, 5 и 10 мин (`ALERT_RETRY_S`), бот при этом работает дальше.
  Строки `[ОТКАТ] Сообщение в Telegram не ушло (...). Пробую снова через N с.` и в конце `... Сообщение в Telegram: отправлено с N-й попытки`.
  Ошибки самого Telegram (неверный токен) не повторяются. Итог сессии — те же повторы, но короче (`main.py:REPORT_RETRY_S`: 10 и 30 с),
  при Ctrl+Shift+Q — одна попытка. SOS из окна программы (`ui/`) пока шлётся один раз.
- Язык сообщений Telegram — язык окна программы (у бота `HEROWARS_LANG` → `main.py:TG_LANG`, у окна `current_lang`).
  Лог и терминал бота остаются по-русски; причины плохого боя и остановки идут в сообщение по-русски (имена титанов —
  на языке окна, `telegram_report.humanize`). Служебные метки (`[SOS_TRIGGER]`, `MANUAL`, ...) не переводятся.

### Как бот выбирает пак (`rules_engine.py`, `bot_data/rules/*.yml`, `profile.yml`)
- Для каждой стихии есть файл `bot_data/rules/<стихия>.yml` (рабочая копия; при первом запуске копируется из `rules/`):
  базовый пак `default_team` и список правил `rules`.
- **Порядок проверки:**
  1. правила `action: skip` — дают «чёрный список» титанов и запрещают двери;
  2. правила спасения (`titan_hp_below`, `titan_energy_below`);
  3. анти-паки (`enemies_contain`);
  4. базовый пак.

  Внутри группы правила проверяются сверху вниз.
- **Особые значения:**
  - пак `[STOP]` — остановиться и спросить;
  - `require_fought` — титан уже должен был провести бой в этом запуске;
  - `allowed_delta` — свой допуск потерь;
  - `special_ult: angus` — действует, только если включён переключатель ручной ульты Ангуса (задача 12); новые правила бот этой пометкой не помечает.
- **Пороги** из `profile.yml` (все читает `tactics.Settings`): `critical_hp` (порог паники, %), `max_hp_delta` (допуск потерь
  за бой, %), `group_loss_titans`/`group_loss_percent` (общие потери пака, по умолчанию 3 титана по 40%, 0 — выключено),
  `titan_critical_hp` (личные пороги паники `{титан: %}`, по желанию). Настройки бота «решает сам»: `auto_rollback`,
  `auto_rollback_tries`, `backup_teams`, `door_order`, `sos_timeout_minutes` (задача 9б), `heal_below_hp` (лечить ниже N% ХП, 0 — не собирать
  пак отхила) и `heal_remove_order` (кого убирать из пака ради раненого, до 3 титанов; задача 9в). Всё это задаётся в окне программы: переключатель во вкладке
  «Мастер правил» (`ui/rules_tab.py`, сохраняется сразу) и окно «⚙️ Тактика» (`ui/tactics_dialog.py`, читает и пишет
  через `tactics.read_tactics`/`write_tactics`, остальное в профиле не трогает). Бот берёт их при следующем запуске фарма.
- **Устаревшие правила** (`rules_engine.OBSOLETE_RULES`) бот удаляет из `bot_data/rules/*.yml` при запуске (удалить решил
  пользователь): «Авто-отхил (araji < 65%)» с Ригелем и допуском 6%; анти-паки огня из сессии 07, которые бот запомнил сам
  (`source: auto`): против Ангуса, Сильвы, Вердока с Молохом и против Ангуса, Авалона, Эдема с Алекто.
- **«Золотые правила» сами** (задача 9б, только если бот решает сам, при запуске; `main.py:add_golden_rules`): пак, который
  против этого состава врагов провёл 5 боёв и больше и выиграл 80% и больше (как кнопка во вкладке «Аналитика»), становится
  анти-паком «Золотое правило против: ...» (`source: golden`). Не берутся: базовый пак, паки правил отхила и спасения,
  ваши запасные паки, паки отхила, которые бот собрал сам (`heal_for`), паки с титанами не из ваших правил и паков
  (`own_titans`), враги, против которых правило уже есть.
  Бой считается плохим (`battle_verdict.py:evaluate_battle`, вызывается из `main.py` в `WAIT_FOR_OK`), если:
  кто-то умер или его иконка не найдена, у кого-то ХП ниже порога паники (личного или общего), кто-то потерял больше допуска,
  N титанов и больше потеряли по X% (общие потери),
  либо правило отхила (`titan_hp_below`) сработало *из-за этого боя* (до боя нет, после есть, у титана, который дрался).
  Движок правил после боя заново **не** спрашивается. Правила по энергии и `skip` на итог боя не влияют — они работают перед следующим боем.
- **Состояние титанов** (`GLOBAL_TITAN_STATE`: ХП и энергия после последнего боя) — `titan_state.TitanMemory`: сохраняется
  в `bot_data/titan_state.json` при каждом `update`/`clear` и загружается при запуске, если игровой день тот же
  (`stats_manager.get_game_date`, `reset_hour`). В новый игровой день (в коридоре) очищается. Очищается и после мягкой паузы
  и ручного боя (ХП бот не видел). С задачи 9в перед каждым боем ХП и энергия титанов в слотах берутся с экрана выбора команды,
  поэтому после вашей ручной игры цифры снова верные с первой же комнаты (для титанов, которые стоят в слотах).
- **История боёв для тактики** (`tactics.BattleHistory`): при запуске читается `bot_data/logs/*.jsonl` (по времени), новые бои
  добавляются через `main.py:record_battle` (`analytics.log_battle` возвращает запись). С задачи 9б в записи есть `hp_before`
  (ХП до боя); в старых записях оно восстанавливается по прошлым удачным боям того же игрового дня. Откат считается поражением
  пака, только если виноваты враги (бой был бы плохим и со 100% ХП, по **нынешним** порогам). Сессия 07, комната 74:
  откат из сессии 06 (допуск тогда 20%) по нынешнему допуску 60% не поражение — обычный пак, не Алекто.
  С задачи 9в в записи и энергия до боя (`energy_before`, в старых записях восстанавливается так же). Прогноз потерь
  (`expected_loss`) берёт бои, где энергия титана была похожей (±25%), если таких хотя бы 2: Араджи с 60–80% энергии
  в огне теряет мало (ваш ответ на вопрос 22).
- Правила читаются один раз при запуске. Если поменять их в GUI во время работы, бот этого не увидит.

### Как бот видит и нажимает (`vision.py`)
- Снимок окна scrcpy делается через `mss` (`vision.grab_frame`; при заблокированном ПК ждёт разблокировки).
  В первый раз бот находит в окне область игры без рамок и чёрных полос и считает масштаб от высоты 720 (`_calibrate_geometry`).
  Эталонный размер окна — 1606×748, масштаб около 0,978.
- Шаблон берётся из `assets/<ЯЗЫК>/имя.png`, если такой есть, иначе из `assets/имя.png`, и масштабируется.
- **Часть картинки** (`vision.TEMPLATE_CROP`, задача 8б): у `btn_retry.png` ищется только середина — надпись «Ещё раз».
  На окне результата три кнопки: «Ещё раз», синяя «Инфо» (открывает окно «Статистика победы», бот его не знает) и «ОК».
  Вся картинка «Ещё раз» совпадала с «Инфо» на 0,90 (с собой — 0,91–0,93), и в сессии 10 бот нажал «Инфо» вместо «Ещё раз».
  Надпись: с собой 0,88–0,94, с «Инфо» — не больше 0,61. Если новая картинка похожа на соседнюю кнопку — так же.
  Крестик закрытия окон бот не жмёт: в коридоре такой же крестик — выход из подземелья.
- Пороги совпадения: обычно 0,75–0,8; титаны в слотах — 0,88; враги — 0,72; иконки на окне результата — 0,62.
- **Полоски на экране выбора команды** (задача 9в, `analyzer.read_bars_under_icon`): под иконкой титана зелёная (ХП) и под ней
  жёлтая (энергия). Пустая часть полоски почти чёрная (V ≤ 45, S < 180). Длину полоски бот меряет сам (заливка + чёрная часть
  до рамки), поэтому размер окна не важен. Нет зелёной полоски — ХП не прочиталось. Настроено по `pered_boem.png`
  (полная полоска 64–65 пикселей при высоте игры 713).
- Каждый вызов `get_match_loc` делает **новый снимок экрана**. `get_first_match` ищет сразу несколько картинок на одном снимке (так работает откат).
  С задачи 11 — один снимок на шаг: `game_frame` + `find_on_frame` или `find_many` (коридор, начало боя, ожидание окна результата).
- **Быстрый поиск** (задача 11, `vision.match_scores`, `best_match`): сначала по снимку и картинке, уменьшенным в 2 раза, потом точно —
  только там, где совпадение может быть не ниже порога (запас `COARSE_MARGIN` 0,2; на скриншотах падение не больше 0,08).
  Числа и места те же, что у `cv2.matchTemplate` (`tests/test_fast_match.py`). Картинки меньше 24 пикселей ищутся как раньше.
  Новый поиск картинки — тоже через `best_match`/`match_scores`, а не `cv2.matchTemplate` по всему снимку.
- **Часть экрана** (`vision.Area`, `vision.AREAS`): где искать кнопку. Части считаются в долях высоты от левого края, середины
  или правого края (игра растягивает интерфейс по высоте). Есть для «ОК», «Ещё раз», «x2», флажка, «Автобой»/«В бой!»,
  иконок окна результата (`analyzer.RESULT_AREA`), слотов и сетки (`team_manager.SLOTS_AREA`, `GRID_AREA` — панель слева).
  Кнопки, которых нет на скриншотах (пауза, «Отступить», «Забрать», «Активировать», «Атаковать»), ищутся по всему окну.
  Новую часть добавляй, только проверив на скриншоте, и добавь его в `tests/test_fast_match.py`.
  У `match_many_on_frame` и `find_on_frame` `x`, `y` — от левого верхнего угла снимка, `ox`, `oy` — сдвиг снимка в окне.
- **Нажатие.** Координаты переводятся в пиксели телефона (`adb shell wm size`) и отправляются через
  одно постоянное соединение `adb shell sh` (задача 11, `adb_shell.AdbShell`, `vision.ADB`, `vision.adb_input`): после каждой команды
  телефон печатает метку, по ней `ShellCommand` ведёт себя как процесс (`poll`, `wait`). Нет соединения — по-старому,
  `subprocess.Popen(["adb", "shell", "input", "tap", ...])`; обрыв — строка `[ADB] ... оборвалось`, переподключение не чаще раза в 5 с.
  `click_human` возвращает этот процесс (или `ShellCommand`). Свайп (`swipe_scrcpy`) ждёт, пока выполнится на телефоне.
  При запуске `vision.measure_adb` (в отдельном потоке): пустая команда новым adb и через соединение — строка `[ADB] Пустая команда ...`,
  в `[ИТОГ]` — «Из чего складывается нажатие: запуск нового adb на ПК, связь с телефоном, команда input на телефоне».
  **Пауза реакции** (задача 10, вопрос 13; `click_logic.TapPacer`, `vision.TAP_PACER`): перед нажатием бот ждёт, чтобы
  с момента, когда кнопка **появилась** на экране (`seen_at`), прошло случайно 0,3–0,8 с, и не жмёт чаще 2 раз в секунду
  (0,5 с между нажатиями). Паузы после нажатия нет. Если бот после появления кнопки и так думал дольше (читал ХП, разбирал двери),
  ждать не нужно, поэтому `seen_at` передаётся: дверь — первый снимок с флажком, «Атаковать» — когда открылось окно выбора комнат,
  «Авто»/«В бой» — когда появился экран выбора команды (`main.py:TEAM_SEEN`), «ОК» — когда появилось окно результата,
  титаны — снимок, на котором их нашли, Ангус — когда начался бой. Без `seen_at` `find_and_click_bulletproof` считает от
  первого снимка с кнопкой. В `[ИТОГ]` строка «Пауза реакции перед нажатием: ждал N раз из M ...». Новые нажатия — тоже через `click_human`.
  Бот сам нажатие не ждёт, но по процессу знает, когда команда дошла до телефона (`click_logic.TapWatch`).
  Задержка нажатия измеряется в `[ИТОГ]` (строка «Нажатия adb tap»).
  Точка нажатия случайная внутри кнопки (по 20% от краёв не трогает). Для двери — случайная точка в центральной половине зоны под флажком
  (`click_logic.door_click_zone`).
- **Повторное нажатие** (`vision.find_and_click_bulletproof`, правило в `click_logic.RetryPolicy`): бот жмёт кнопку один раз
  и ждёт, пока она пропадёт. Жмёт снова, только если через 4 с **после того, как команда дошла до телефона** экран не отреагировал
  (после нажатия окно часто «думает» — затемнение и кружок загрузки, ~3 с; при 1,5 с бот жал во время загрузки).
  Если кнопка бледнеет или сдвигается (окно закрывается), ждёт дольше, но не больше 8 с.
  Кнопка пропала — успех, только если её нет и на снимке через `click_logic.GONE_CONFIRM_S` (0,25 с): частые снимки (задача 11)
  ловят мгновенное «мигание» кнопки при нажатии, и бот считал окно «ОК» закрытым через 0,7 с вместо обычных ~2,6 с.
  Так же работает «Атаковать» в `combat.find_smart_door`. В логе повтор виден строкой `Клик по '...' не зарегистрирован сервером`.
- **Дверь** (`navigation.smart_navigate_hallway`): бот жмёт, только когда флажок стоит на месте
  (3 снимка подряд в одной точке ±3 пикселя, не меньше 0,2 с; если не встал за 3 с — жмёт как есть).
  Пока флажок едет, бот смотрит только на него, «Атаковать» не ищет (задача 10).
  Если окно «Атаковать» не открылось за 2 с после того, как нажатие дошло до телефона, — это промах (`door_misses`),
  бот сразу смотрит флажок заново.
- **Окно выбора комнат** (задача 10, вместо пауз 0,2 + 0,2 с): `vision.wait_after_tap` возвращает, когда и где увидел кнопку
  «Атаковать», навигация кладёт это в `navigation.ROOM_WINDOW`, `main.py` передаёт в `find_smart_door(opened=take_room_window())`.
  `combat.wait_room_window_still` разбирает двери по снимку, где кнопки «Атаковать» стоят на том же месте (±3 пикселя),
  что и на предыдущем снимке не меньше 0,3 с назад (`click_logic.spots_still`); не замерли за 2 с — разбирает как есть;
  кнопок ещё нет (окно проявляется) — ждёт их до 2 с, потом «Двери не найдены» и коридор.
  Центр каждой кнопки — точка лучшего совпадения (`combat._find_attack_buttons`), поэтому он не скачет между снимками.
  С задачи 11 враги (`scan_enemy_team(screen=...)`) и первое нажатие «Атаковать» — по этому же замершему снимку, без нового.
- **Переход на новый этаж:** после «Забрать» бот ждёт, пока появится флажок двери (`navigation.wait_for_new_floor`, не дольше 12 с).
  Спуск идёт ~8–10 с, и всё это время «Активировать» ещё виден, поэтому раньше в коридор возвращаться нельзя.
  Строка в логе: `На новом этаже появилась дверь через N с после награды`. Ожидание «картинка замерла» пробовали в задаче 4,
  но на фоне всегда что-то шевелится (10 раз из 10 не сработало), его убрали.
- **Начало боя** (`main.py`, `PREP_AUTO`): «Авто» жмётся через `find_and_click_bulletproof`, то есть с проверкой и повтором.
  Если боя нет через 10 с, а на экране всё ещё выбор команды, бот возвращается в `SET_TEAM` и жмёт снова (до 3 раз подряд).
  Не помогло — похоже, нет связи (задача 8б, сессия 10): бот **не выключается**, как раньше, а ждёт 30 с, 1, 2, 4, 8 мин
  (`click_logic.START_SLOW_WAITS_S`, `main.py:wait_for_server`, строка `[СЕТЬ] Бой не начался N раз(а) подряд ... Жду N с`) и жмёт снова.
  Не помогло и это (~15 мин) — скриншот `start_fail_...png`, сообщение в Telegram и мягкая пауза. Решение в `click_logic.after_failed_battle_start`
  (`main.py:handle_failed_start`). Так же с «В бой» для Ангуса: если она не нажалась.
  Если бот в состоянии `HALLWAY`, а на экране выбор команды (таймаут коридора 10 с), он возвращается в `SET_TEAM`;
  если на экране окно результата («ОК») — в `WAIT_FOR_OK` (бой закончился позже, чем бот его ждал; сессия 06).
- **Задержка нажатия.** По замеру сессии 05 (`[ИТОГ]`) одно `adb tap` занимает в среднем 0,42 с, максимум 3,2 с.
  В строке «не зарегистрирован сервером» теперь пишется, сколько секунд выполнялось нажатие, а в следующей строке — через сколько
  после повтора кнопка пропала. По ним видно, теряются ли нажатия или окно просто медленно закрывается.
- **Свайп** — `input swipe` (0,4 с) через постоянное соединение; бот ждёт, пока он выполнится (не дольше 3 с), паузы 0,6 с больше нет.
  Остановку сетки после свайпа проверяет `team_manager.swipe_grid`.

## За что отвечает каждый файл

| Файл | Что делает |
|---|---|
| `gui.py` | Точка входа: окно программы, вкладки, язык. С флагом `--bot-mode` запускает бота (для .exe) |
| `main.py` | Сам бот: машина состояний, решение после боя, SOS, откат, статистика сессии, лимиты. **Запускает бота сразу при импорте** |
| `vision.py` | Снимки экрана, поиск картинок (быстрый поиск `match_scores`/`best_match`, части экрана `Area`/`AREAS`, один снимок на несколько картинок `find_many` — задача 11), калибровка масштаба, нажатия и свайпы через ADB (`adb_input`, замер `measure_adb`) |
| `adb_shell.py` | Одно постоянное соединение `adb shell` для нажатий и свайпов (задача 11): метка после каждой команды, переподключение, замер пустой команды новым adb (`spawn_seconds`). Без OpenCV, проверяется тестами на поддельном adb |

## Как запустить бота на ПК пользователя (Windows)

### Один раз
1. Python 3.11 или новее с python.org. При установке поставить галочку «Add python.exe to PATH».
   Библиотеки в `requirements.txt` свежие: numpy 2.5 на Python 3.10 не ставится, хотя README пишет «3.10+».
2. scrcpy (в комплекте есть adb). Распаковать и добавить папку в PATH.
   Проверка в cmd: `adb devices` показывает телефон со статусом `device`; `scrcpy --version` работает.
3. На телефоне включить «Отладка по USB» и «Отладка по USB (настройки безопасности)». Без второго пункта нажатия не работают.

### Обычный запуск
1. Запускать всегда **из папки проекта**: пути к `profile.yml`, `rules/`, `bot_data/` относительные.
2. Двойной клик по `start.bat`. В первый раз он создаст `venv` и поставит библиотеки (несколько минут), потом откроет окно программы.
   То же самое вручную в cmd из папки проекта:
   ```
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   python gui.py
   ```
3. В окне программы:
   1. «1. Подключить телефон» — появится окно `HeroWarsBot_Arena`;
   2. в игре зайти в подземелье и встать в коридоре;
   3. «2. Начать фарм».
4. Если после обновления кода поменялся `requirements.txt`, ещё раз выполнить `venv\Scripts\activate` и `pip install -r requirements.txt`.

### Запуск бота без окна программы (для отладки)
```
scrcpy --window-title HeroWarsBot_Arena --stay-awake
```
Во втором окне cmd из папки проекта:
```
venv\Scripts\activate
set HEROWARS_LANG=RU
python -X utf8 -u main.py
```
- Ответ на окно SOS печатается прямо в это окно: `IGNORE`, `STOP`, `MANUAL`, `ROLLBACK:hyperion,sigurd,tidus,nova,mairi`, `CONFIRM`.
- Размер окна scrcpy так не подгоняется, а он должен быть около 1606×748. Проще запускать через GUI (там есть кнопка «Сброс размера»).

`test_ui_kit.py` — задача 15: цвета как в `design/theme.py`, титаны и иконки на месте, надписи без эмодзи на 13 языках, витрина собирается). Ограничения:
- **Окно программы в облаке** (новый интерфейс, задача 15). У основного Python нет tkinter, у `python3.12` — есть после
  `apt-get install -y python3-tk fonts-roboto` (сначала `apt-get update`). Потом
  `python3.12 -m pip install --break-system-packages customtkinter==6.0.0 pillow pyyaml pytest` и
  `xvfb-run -a python3.12 -m pytest tests/test_ui_kit.py`. Скриншот окна на виртуальном экране — `PIL.ImageGrab.grab(bbox=...)`
  (`xvfb-run -a -s "-screen 0 1100x720x24" python3.12 скрипт.py`): так каждый экран сверяется с `design/screenshots/`.
- **`main.py` запускает бота прямо при импорте** (цикл `while True` на уровне модуля), поэтому импортировать его в тестах нельзя.
  Логику, которую надо проверить, выносим в отдельные функции или модули.
- **`pygetwindow` на Linux падает уже при импорте.** Поэтому `vision.py`, `analyzer.py`, `navigation.py`,
  `combat.py`, `team_manager.py`, `environment.py` в облаке без заглушки не импортируются.
  В тесте до импорта: `sys.modules["pygetwindow"] = types.ModuleType("pygetwindow")`.
  `ctypes.windll` (горячие клавиши) есть только в Windows.
- **`rules_engine.py` при импорте читает** `profile.yml` и `rules/*.yml` из текущей папки (`engine = RulesEngine()`).
  В тестах переходи во временную папку (`monkeypatch.chdir(tmp_path)`) и создавай `RulesEngine()` там.
- **`analytics.py` при импорте удаляет лишние старые файлы в `bot_data/logs/`** и создаёт эту папку. Импортируй его только после
  `monkeypatch.chdir(tmp_path)` (и удали из `sys.modules`, если он уже импортирован) — пример в `tests/test_data_paths.py`.
- **`data_paths.ensure_bot_data()` помнит папку, которую уже проверил.** В тестах перед каждым тестом очищай `data_paths._CHECKED`.
- Распознавание можно проверять на скриншотах пользователя (`tests/data/screens/`, формат webp без потерь) и шаблонах из `assets/`:
  `cv2.imread` работает и в облаке. Например, на `result_54.webp` и `result_111.webp` видно окно результата, а в логе есть правильные ХП
  (54: Араджи 100, Гиперион 100, Ригель 55, Ияри 100, Люмира 100; 111: 56, 59, 81, 38, 44).
- История боёв (`logs/*.jsonl`, а в новых сессиях `bot_data/logs/*.jsonl`) и логи сессий можно разбирать скриптами — так удобно проверять новую логику на настоящих данных.

## Правила работы
1. **Одна задача — одна сессия.** Меняй только файлы, нужные для этой задачи.
   Задачи берём из `PLAN.md` по порядку, если пользователь не сказал иначе.
2. **Если логику можно проверить без игры — пиши тесты и запускай их.** В отчёте пиши, какие тесты прошли.
3. **В конце каждой сессии напиши пользователю по-русски простыми словами:**
   - что изменил;
   - зачем;
   - как проверить в игре: по шагам, что запустить и на какие строки лога смотреть;
   - что он должен сделать руками (например, добавить картинку, поменять настройку, удалить или перенести файл).
4. Бота в облаке не запускать. Большие логи целиком не читать.
5. Не ломать связь GUI и бота (`[SOS_TRIGGER]`, команды через stdin, `pause.flag`), пока `ui/` не трогаем.
6. **Действия должны оставаться человеческими:** случайная точка нажатия, пауза реакции, никаких серий быстрых нажатий.
   Ускоряем бота, убирая лишние ожидания, повторы и проверки, а не делая нажатия быстрее человека.
7. Не коммить `profile.yml`, токены и chat_id. Файлы, которые бот пишет на ПК, — в `bot_data/` (она в `.gitignore`), не в `logs/`; путь бери из `data_paths.py`.
8. **Пиши код как в остальном проекте:** комментарии и сообщения лога по-русски,
   сообщения лога с тегом в квадратных скобках (`[НАВИГАЦИЯ] ...`, `[КОМАНДА] ...`).
9. Сделал задачу — отметь её в `PLAN.md`. Поменялось устройство бота — обнови этот файл.
10. Ничего не удаляй и не переименовывай из файлов пользователя (`logs/`, `rules/`, `stats.json`, `bot_data/`, `profile.yml`) без его согласия.
