# CLAUDE.md — памятка для работы над HeroWarsBot

## Кто пользователь и как с ним говорить
- Пользователь не программист, пишет код с помощью ИИ.
- Объясняй простым языком, как старшекласснику. Пиши по-русски.
- Термины расшифровывай, а вместо длинных рассуждений давай короткие шаги.

## О проекте: главные факты
- Бот для Hero Wars на Python. Он проходит подземелье титанами.
- Игра идёт на Android-телефоне, подключённом к ПК (Windows) по USB.
- Экран телефона показывается в окне scrcpy с заголовком `HeroWarsBot_Arena`.
- Бот делает снимки этого окна (`mss`), ищет на них картинки-шаблоны через OpenCV (`cv2.matchTemplate`)
  и нажимает на телефоне через ADB (`adb shell input tap` / `swipe`).
- **Запустить бота здесь, в облаке, нельзя:** нет телефона, игры и scrcpy. Не пытайся. Проверяет пользователь сам у себя на ПК.
- **Картинки.** Полный набор — папка `assets/`, она есть в репозитории.
  - Файла с картинками в base64 (`assets_db.py`) сейчас в репозитории нет: его удалили 13.09.2026, он остался только в истории git.
  - На ПК пользователя его тоже нет: в логе строка «Файл assets_db.py не найден. Использую чтение с диска».
  - Если этот файл появится, бот будет брать картинки из него, а не из `assets/` (`vision.py:15-22`, `vision.py:146-163`).
    Тогда после замены картинки в `assets/` его нужно пересобрать или удалить.
- **`assets/` есть в `.gitignore`.** Картинки, которые уже в репозитории, git продолжает отслеживать.
  Новую картинку git не увидит — добавлять так: `git add -f assets/имя.png`.
- Если нужно знать, какие картинки есть, или нужны конкретные иконки — попроси пользователя, он пришлёт.
  Пиши точное имя файла и что на картинке должно быть.
- **`ui/`** — графическая оболочка. Пока её не трогаем. Исключение — если задача или пользователь прямо разрешили.
- **`logs/`** заполняет сам пользователь.
  - Если бот сохраняет файлы на ПК, они должны лежать в другой папке, добавленной в `.gitignore` (по плану это `bot_data/`).
  - Сейчас бот ещё пишет туда историю боёв (`analytics.py`) — это исправит задача 2 из `PLAN.md`.

## Что лежит в `logs/`
- **`logs/*.jsonl`** — история боёв, её пишет сам бот (`analytics.py`).
  - Одна строка — один бой: точное время (`timestamp`), комната, враги, пак,
    результат (`SUCCESS` или `ROLLBACK`), причина, ХП и энергия титанов.
  - Имя файла — время запуска бота.
  - Рядом лежит `logs/battle_log.csv` — короткая версия по всем запускам.
- **`logs/session_XX/observations.txt`** — замечания пользователя во время игры.
  - Вверху дата и время начала сессии. По ним найди бои этой сессии в `.jsonl`.
  - Номер комнаты в замечаниях — число из строки `[СТАТИСТИКА] Комнат: N`, которое пользователь видел последним.
    Значит, ошибка случилась после этой строки в логе (плюс-минус одна комната).
  - Замечания надиктованы голосом, номера иногда расслышаны неточно.
- **`logs/session_XX/log.txt`** (может называться `gui_log_<дата>.txt`) — полный лог из окна бота.
  - Времени в нём нет (пока не сделана задача 1). Комнаты разделяются строками `[СТАТИСТИКА] Комнат: N`.
  - В одном логе может быть несколько запусков бота. Каждый начинается строкой
    `[АНАЛИТИКА] Логи сессии будут сохранены в: logs/battle_log_<время>.jsonl`, и счёт комнат идёт заново.
  - Лог длинный: **целиком не читай**. Ищи нужные места поиском (`grep -n`) или напиши маленький скрипт.
    Как это делалось — в `docs/analysis_session_01-02.md`.
- **`logs/session_XX/screens/`** — скриншоты пользователя, в имени файла номер комнаты.
- Папка может называться по нескольким сессиям (например `session_01-02`). Тогда ориентируйся на большую сессию.

## Как устроен бот

### Два процесса
1. **`gui.py`** — окно программы (библиотека customtkinter).
   - Кнопка «1. Подключить телефон» запускает scrcpy (`environment.py`).
   - Кнопка «2. Начать фарм» подгоняет окно scrcpy под 1606×748 и запускает бота отдельным процессом:
     `python -X utf8 -u main.py`. В собранном .exe вместо этого `<exe> --bot-mode`.
   - Язык игры передаётся боту через переменную окружения `HEROWARS_LANG`.
2. **`main.py`** — сам бот.
   - Всё, что он печатает (`print`), GUI показывает в чёрном окне лога (`ui/dashboard.py:327-384`).
   - В файл лог сейчас сохраняется только кнопкой «Сохранить лог».

### Связь GUI и бота — не ломать, пока `ui/` не трогаем
- **Бот → GUI:** строка с `[SOS_TRIGGER]`, после неё JSON:
  - `{"titans": {...}, "is_manual": ...}` — плохой бой, окно «Требуется вмешательство»;
  - `{"type": "NO_VALID_TEAM", ...}` — правила не дают подходящего пака;
  - `TEST_SUCCESS:{...}` — тестовый пак выиграл, нужно подтверждение.
- GUI ищет эти строки через `in` (`ui/dashboard.py:341-374`). Время в начале строки допустимо,
  а сам маркер и JSON после него менять нельзя.
- Строка с `[ПАУЗА ОТЛАДКИ]` включает в GUI кнопку «Продолжить».
- **GUI → бот:** одна строка в stdin: `IGNORE`, `MANUAL`, `STOP`, `ROLLBACK:титан1,титан2,...`,
  `ROLLBACK_TG:...` (из Telegram), `CONFIRM`, `NEW_PACK:...`.
- **Мягкая пауза** — файл `pause.flag` в папке бота. Его создаёт GUI, а при сбое отката — сам бот.
  Пока файл есть, бот ждёт в коридоре.
- **Горячие клавиши** (`main.py:69-90`): Ctrl+Q — остановиться после текущего боя; Ctrl+Shift+Q — остановиться сразу.

### Цикл одной комнаты (машина состояний в `main.py`)
Порядок состояний: `HALLWAY` → `ROOM_SELECTION` → `SET_TEAM` → `PREP_AUTO` или `PREP_SPECIAL_ANGUS` → `WAIT_FOR_OK` → снова `HALLWAY`.

1. **HALLWAY** (`navigation.py`). Ищет кнопку «Атаковать», флажок двери или точку сохранения.
   - Флажок → нажать на дверь.
   - Точка сохранения (конец этажа) → «Активировать» → «Забрать» → пауза 4 секунды.
2. **ROOM_SELECTION** (`combat.py:find_smart_door`).
   - Находит кнопки «Атаковать» и по иконке определяет стихию двери (water / mix / earth / fire).
   - Выбирает дверь: вода → микс → земля → огонь, с учётом правил `skip`.
   - Распознаёт врагов (`analyzer.py:scan_enemy_team`) и жмёт «Атаковать».
3. **SET_TEAM**. Ждёт экран выбора команды и спрашивает у движка правил, какой пак ставить.
   - Если этот пак уже стоял в этой стихии в текущем запуске (`LAST_USED_TEAMS`), сборку пропускает.
   - Иначе собирает пак (`team_manager.py:verify_and_set_team`).
4. **PREP_AUTO** — жмёт «Авто», бой идёт в автобое.
   **PREP_SPECIAL_ANGUS** — если в паке Ангус и включён ручной контроль: жмёт «В бой», включает автобой
   на 1,8 с для ульты Ангуса и выключает его (`combat.py:execute_angus_ult`).
5. **WAIT_FOR_OK**. Ждёт кнопку «ОК» окна результата, потом ещё 1,5 с, затем читает ХП и энергию по полоскам
   (`analyzer.py:scan_team_health`) и проверяет пороги и правила.
   - **Всё хорошо:** пишет бой в историю и статистику, печатает `[СТАТИСТИКА] Комнат: N`, жмёт «ОК».
   - **Плохо:** печатает `[SOS_TRIGGER]` и ждёт решения.
   - **Решение «откат»:** `combat.py:execute_rollback` («Ещё раз» → пауза → «Отступить» → коридор).
     Новый пак проверяется в той же комнате. После подтверждения сохраняется правило (`rules_engine.py:learn_new_rule`).
6. Перед каждой дверью бот проверяет лимиты сессии: время, комнаты, этажи, титанит (`main.py:get_stop_reason`).

Важно: в `SET_TEAM` и `WAIT_FOR_OK` нет ограничения по времени. Если на экране не то, что бот ждёт, он ждёт бесконечно.
Защита только одна: если виден флажок двери, бот возвращается в коридор.

### Как бот выбирает пак (`rules_engine.py`, `rules/*.yml`, `profile.yml`)
- Для каждой стихии есть файл `rules/<стихия>.yml`: базовый пак `default_team` и список правил `rules`.
- **Порядок проверки:**
  1. правила `action: skip` — дают «чёрный список» титанов и запрещают двери;
  2. правила спасения (`titan_hp_below`, `titan_energy_below`);
  3. анти-паки (`enemies_contain`);
  4. базовый пак.

  Внутри группы правила проверяются сверху вниз.
- **Особые значения:**
  - пак `[STOP]` — остановиться и спросить;
  - `require_fought` — титан уже должен был провести бой в этом запуске;
  - `allowed_delta` — свой допуск потерь;
  - `special_ult: angus`.
- **Пороги** из `profile.yml`: `critical_hp` (порог паники, %) и `max_hp_delta` (допуск потерь за бой, %).
  Бой считается плохим, если кто-то умер, у кого-то ХП ниже порога паники или кто-то потерял больше допуска (`main.py:263-300`).
- **Состояние титанов** (`GLOBAL_TITAN_STATE`: ХП и энергия после последнего боя) хранится только в памяти
  и пропадает при перезапуске бота.
- Правила читаются один раз при запуске. Если поменять их в GUI во время работы, бот этого не увидит.

### Как бот видит и нажимает (`vision.py`)
- Снимок окна scrcpy делается через `mss`.
  В первый раз бот находит в окне область игры без рамок и чёрных полос и считает масштаб от высоты 720 (`_calibrate_geometry`).
  Эталонный размер окна — 1606×748, масштаб около 0,978.
- Шаблон берётся из `assets/<ЯЗЫК>/имя.png`, если такой есть, иначе из `assets/имя.png`, и масштабируется.
- Пороги совпадения: обычно 0,75–0,8; титаны в слотах — 0,88; враги — 0,72; иконки на окне результата — 0,62.
- Каждый вызов `get_match_loc` делает **новый снимок экрана**.
- **Нажатие.** Координаты переводятся в пиксели телефона (`adb shell wm size`) и отправляются через
  `subprocess.Popen(["adb", "shell", "input", "tap", ...])`.
  **Бот не ждёт, пока команда выполнится**, и до телефона она доходит с задержкой.
  Точка нажатия случайная внутри кнопки (по 20% от краёв не трогает). Для двери — случайная точка в зоне под флажком.
- **Свайп** — `adb shell input swipe` (0,4 с), после него пауза 0,6 с.

## Как запустить бота на ПК пользователя (Windows)

### Один раз
1. Python 3.11 или новее с python.org. При установке поставить галочку «Add python.exe to PATH».
   Библиотеки в `requirements.txt` свежие: numpy 2.5 на Python 3.10 не ставится, хотя README пишет «3.10+».
2. scrcpy (в комплекте есть adb). Распаковать и добавить папку в PATH.
   Проверка в cmd: `adb devices` показывает телефон со статусом `device`; `scrcpy --version` работает.
3. На телефоне включить «Отладка по USB» и «Отладка по USB (настройки безопасности)». Без второго пункта нажатия не работают.

### Обычный запуск
1. Запускать всегда **из папки проекта**: пути к `profile.yml`, `rules/`, `logs/`, `stats.json` относительные.
2. Двойной клик по `start.bat`. В первый раз он создаст `venv` и поставит библиотеки (несколько минут), потом откроет окно программы.
   То же самое вручную в cmd из папки проекта:
   ```
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   python gui.py
   ```
3. В окне программы:
   1. «1. Подключить телефон» — появится окно `HeroWarsBot_Arena`;
   2. в игре зайти в подземелье и встать в коридоре;
   3. «2. Начать фарм».
4. Если после обновления кода поменялся `requirements.txt`, ещё раз выполнить `venv\Scripts\activate` и `pip install -r requirements.txt`.

### Запуск бота без окна программы (для отладки)
```
scrcpy --window-title HeroWarsBot_Arena --stay-awake
```
Во втором окне cmd из папки проекта:
```
venv\Scripts\activate
set HEROWARS_LANG=RU
python -X utf8 -u main.py
```
- Ответ на окно SOS печатается прямо в это окно: `IGNORE`, `STOP`, `MANUAL`, `ROLLBACK:hyperion,sigurd,tidus,nova,mairi`, `CONFIRM`.
- Размер окна scrcpy так не подгоняется, а он должен быть около 1606×748. Проще запускать через GUI (там есть кнопка «Сброс размера»).

## Как проверять без игры (тесты в облаке)
Установка и запуск (проверено, в облаке ставится):
```
pip install pyyaml numpy opencv-python-headless pytest
python -m pytest -q
```

Тесты кладём в папку `tests/`. Ограничения:
- **`main.py` запускает бота прямо при импорте** (цикл `while True` на уровне модуля), поэтому импортировать его в тестах нельзя.
  Логику, которую надо проверить, выносим в отдельные функции или модули.
- **`pygetwindow` на Linux падает уже при импорте.** Поэтому `vision.py`, `analyzer.py`, `navigation.py`,
  `combat.py`, `team_manager.py`, `environment.py` в облаке без заглушки не импортируются.
  В тесте до импорта: `sys.modules["pygetwindow"] = types.ModuleType("pygetwindow")`.
  `ctypes.windll` (горячие клавиши) есть только в Windows.
- **`rules_engine.py` при импорте читает** `profile.yml` и `rules/*.yml` из текущей папки (`engine = RulesEngine()`).
  В тестах переходи во временную папку (`monkeypatch.chdir(tmp_path)`) и создавай `RulesEngine()` там.
- **`analytics.py` при импорте удаляет старые файлы в `logs/`** — не импортируй его из папки проекта.
- Распознавание можно проверять на скриншотах пользователя (`logs/session_*/screens/`) и шаблонах из `assets/`:
  `cv2.imread` работает и в облаке. Например, на `54.png` и `111.png` видно окно результата, а в логе есть правильные ХП
  (54: Араджи 100, Гиперион 100, Ригель 55, Ияри 100, Люмира 100; 111: 56, 59, 81, 38, 44).
- История боёв (`logs/*.jsonl`) и логи сессий можно разбирать скриптами — так удобно проверять новую логику на настоящих данных.

## Правила работы
1. **Одна задача — одна сессия.** Меняй только файлы, нужные для этой задачи.
   Задачи берём из `PLAN.md` по порядку, если пользователь не сказал иначе.
2. **Если логику можно проверить без игры — пиши тесты и запускай их.** В отчёте пиши, какие тесты прошли.
3. **В конце каждой сессии напиши пользователю по-русски простыми словами:**
   - что изменил;
   - зачем;
   - как проверить в игре: по шагам, что запустить и на какие строки лога смотреть;
   - что он должен сделать руками (например, добавить картинку, поменять настройку, удалить или перенести файл).
4. Бота в облаке не запускать. Большие логи целиком не читать.
5. Не ломать связь GUI и бота (`[SOS_TRIGGER]`, команды через stdin, `pause.flag`), пока `ui/` не трогаем.
6. **Действия должны оставаться человеческими:** случайная точка нажатия, пауза реакции, никаких серий быстрых нажатий.
   Ускоряем бота, убирая лишние ожидания, повторы и проверки, а не делая нажатия быстрее человека.
7. Не коммить `profile.yml`, токены и chat_id. Файлы, которые бот пишет на ПК, — в папку из `.gitignore` (по плану `bot_data/`), не в `logs/`.
8. **Пиши код как в остальном проекте:** комментарии и сообщения лога по-русски,
   сообщения лога с тегом в квадратных скобках (`[НАВИГАЦИЯ] ...`, `[КОМАНДА] ...`).
9. Сделал задачу — отметь её в `PLAN.md`. Поменялось устройство бота — обнови этот файл.
10. Ничего не удаляй и не переименовывай из файлов пользователя (`logs/`, `rules/`, `stats.json`, `profile.yml`) без его согласия.
